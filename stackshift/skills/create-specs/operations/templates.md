# Spec Kit Templates

Templates for spec.md, plan.md, and tasks.md files generated by the create-specs skill.

---

## spec.md Template

Write each feature spec following this structure:

```markdown
# Feature: [Feature Name]

## Status
[One of: COMPLETE / PARTIAL / MISSING with emoji and detail]
- COMPLETE: Feature fully implemented and tested
- PARTIAL: [describe what exists vs what is missing]
- MISSING: Not started

## Overview
[Description of what this feature does]

## User Stories
- As a [role], I want to [action] so that [benefit]

## Acceptance Criteria
- [ ] Criterion 1
- [x] Criterion 2 (checked = implemented)

## Technical Requirements
- Architecture details
- API endpoints
- Data models
- Performance requirements

## Implementation Status
**Completed:**
- Items that exist and work

**Missing:**
- Items that do not exist yet

## Dependencies
- Other features this depends on

## Related Specifications
- Other specs that interact with this one
```

## plan.md Template

Write each implementation plan following this structure:

```markdown
# Implementation Plan: [Feature Name]

## Goal
[One-sentence description of what completing this plan achieves]

## Current State
- What exists today
- What partially works
- What is entirely missing

## Target State
- Complete description of the end state
- All acceptance criteria met
- All technical requirements satisfied

## Technical Approach
1. Step-by-step approach
2. Technology choices with rationale
3. Integration points

## Tasks
- [ ] Task 1 with file path
- [ ] Task 2 with file path

## Risks & Mitigations
- Risk: [description]
  - Mitigation: [approach]

## Testing Strategy
- Unit tests for [area]
- Integration tests for [area]
- E2E tests for [flow]

## Success Criteria
- All acceptance criteria from specification met
- All tests passing
- No regressions
```

## tasks.md Template

Write each task breakdown following this structure:

```markdown
# Task Breakdown: [Feature Name]

## Phase 1: [Phase Name]

### Task 1.1: [Task Name]
- **Status:** Not Started
- **File(s):** `path/to/file.ts`
- **Acceptance Criteria:**
  - [ ] Criterion 1
  - [ ] Criterion 2
- **Notes:** Implementation guidance

### Task 1.2: [Task Name]
...

## Phase 2: [Phase Name]
...

## Testing Phase

### Unit Tests
- [ ] Test case 1
- [ ] Test case 2

### Integration Tests
- [ ] Test case 1

### E2E Tests
- [ ] Test flow 1

## Edge Cases
- Edge case 1: handling approach
- Edge case 2: handling approach

## Dependencies
- External: [dependency]
- Internal: [dependency]

## Acceptance Checklist
- [ ] All phases complete
- [ ] All tests passing
- [ ] Documentation updated
- [ ] No regressions

## Priority Actions
1. Highest impact task
2. Next priority
3. ...
```

Target 300-500 lines per tasks.md file.
